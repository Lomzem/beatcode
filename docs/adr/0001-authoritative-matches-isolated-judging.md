# Authoritative matches with isolated C++ judging

Use Convex as the authority for authorization, match state, card spending, submission order, and results; serve the requested SvelteKit UI as static assets and execute scored C++ in disposable, network-blocked Modal gVisor sandboxes controlled by internal Convex actions. Expected answers and credentials stay outside the contestant boundary, and round winners follow server admission order among accepted submissions so queue speed cannot choose the winner. This preserves the requested stack and a plausible zero-invoice private alpha without administering a judge host; the bounded spike demonstrated feasibility and exposed limits that the implementation must retain.

Modal Starter's timing consistency failed the original target on both tested runtimes. We explicitly accept heterogeneous-host variation for the private alpha, using execution time only as a practical complexity gate, with wide reference-solution margins, per-problem calibration, production recalibration, and no promise that near-threshold solutions behave identically on every host. A sandbox-local crash cannot by itself void a round; reviewed failure attribution separates contestant evidence, unexplained sandbox loss, and independently corroborated platform incidents. Free credits and a custom zero net spend limit bound the monetary goal, not a guarantee of permanent free operation or exhaustive sandbox security.

This ADR records the durable execution, ordering and failure boundaries. [ADR 0002](0002-managed-identity-and-static-delivery.md) records identity and delivery; [ADR 0003](0003-alpha-complexity-calibration.md) records calibration and timing policy. Local planning and spike evidence are intentionally not published. At the original spike checkpoint, all 66 spike sandboxes were finished and no Beatcode app had been deployed; that checkpoint does not establish release acceptance.

## Incident corroboration amendment (2026-10-23)

An unexplained loss inside contestant execution receives one bounded retry, then its contestant verdict, unless an independent platform incident corroborates the loss. Corroboration is an operator-declared incident or a platform-class failure in the same submission's attempt history, within the window from 120 seconds before its first loss through terminal classification. An unrelated attempt's individual failure is insufficient: otherwise a busy deployment could turn a contestant-induced loss into a void. A platform-class failure of the current attempt remains an infrastructure failure. Evidence of a broader outage outside that submission requires an operator declaration; no automatic outage threshold is inferred from unrelated failures.
