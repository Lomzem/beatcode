# Preserve the sandbox reserve during contestant execution

The multi-process allocation probe killed the runner before the 128 MiB low-memory guard could report a verdict, although the sandbox remained alive. A diagnostic with a 512 MiB runtime reserve returned MLE with a valid trailer and a live sandbox. Runtime execution now stops when reported available memory falls below 512 MiB, preserving the reserve already added to each problem's sandbox allocation. Compile mode retains its 128 MiB guard and separate qualification, because a global change would reduce its allowance and reject ordinary compilation.

The reserve alone also lost the runner in a later full qualification run. Runtime execution therefore additionally bounds the sum of virtual address space across processes owned by the contestant to the existing single-process allowance, problem memory plus 80 MiB. This is read from process status rather than approximate sandbox physical-memory telemetry. Shared mappings can count more than once across separate processes; this is a deliberate restriction on process creation and address-space reservation. Per-process address-space and stack limits remain unchanged. Compile has no new aggregate bound because its compiler processes need a separate allowance.

Process reads use one pinned process directory to avoid combining observations from reused PIDs. A single-thread process can release its address space before its state becomes zombie/dead; absent `VmSize` is accepted only with that terminal state or the kernel's `PF_EXITING` flag. An exited leader with live threads still has unknown accounting. Missing or malformed exit flags do not establish exit. This follows the [Linux exit sequence](https://github.com/torvalds/linux/blob/master/kernel/exit.c) and [proc stat contract](https://man7.org/linux/man-pages/man5/proc_pid_stat.5.html); gVisor exposes the flag in its [proc implementation](https://github.com/google/gvisor/blob/master/pkg/sentry/fsimpl/proc/task_files.go).

If accounting remains unknown after bounded process-status revalidation, execution stops without a valid verdict. This remains an uncorroborated sandbox loss under [ADR0001](0001-authoritative-matches-isolated-judging.md), even when the runner reports an accounting error: neither its trailer nor another in-sandbox signal establishes an independent platform incident. The existing bounded retry and incident-corroboration rules apply. A genuine fault without independent corroboration can therefore receive a contestant loss verdict; this is an accepted alpha limitation.

The execution policy is `staged-input-reference-10s-aggregate-vm-v3`; fresh image and immutable environment identities and fresh calibration receipts are required. The physical-memory reserve remains defense in depth, not an exact contestant RSS measurement or a proof against all allocation races. Prior images, observations, failures, decisions and charges remain historical, including failed v1/v2 memory-burst probes. The compiler blow-up, full containment suite, concurrency and production calibration remain release gates.
